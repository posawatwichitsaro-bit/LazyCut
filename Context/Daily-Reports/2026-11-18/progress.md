# LazyCut — 18 พฤศจิกายน 2569

เริ่มตรวจเส้นทางสร้าง Highlight พบว่าเมื่อไม่มี Kill ระบบเดิมนำต้นคลิปมาเรนเดอร์ กำลังแก้ให้จบงานโดยไม่มีไฟล์ และหยุดวิเคราะห์ไฟล์ถัดไปเมื่อมีช็อตเพียงพอ

## ผลการปรับปรุง

- ตัวเฝ้าโฟลเดอร์ลงทะเบียนไฟล์ที่พบ เมื่อไฟล์ใหม่เข้ามาจะยังไม่เรียกตัวตรวจ Kill อัตโนมัติ
- ในงานหนึ่ง Reel ที่ให้ระบบเลือกเหตุการณ์ เมื่อเวลาของช็อตที่ใช้ได้ถึงเพดาน ระบบหยุดก่อนวิเคราะห์ไฟล์ถัดไป การเลือกเหตุการณ์เองผ่าน Preview ยังตรวจรายการที่ผู้ใช้เลือก
- จบงานด้วยสถานะ NO_HIGHLIGHTS เมื่อไม่มีช็อตที่ใช้ได้ หน้า Studio แจ้งผลและล้างลิงก์ดาวน์โหลดเดิม
- ทดสอบซอร์สบน Docker แบบอ่านอย่างเดียว ผ่าน 52 ข้อ ข้าม 1 ข้อเพราะไม่มีคลิปเกมจริง มีคำเตือน deprecation จากไลบรารีทดสอบ 1 รายการ
- งานต่อเนื่อง ได้แก่ ปุ่มเริ่มจากคิวโฟลเดอร์โดยอัตโนมัติ ประวัติช็อตข้ามงานและการย้ายไฟล์ การส่งออกหลาย Reel คะแนนหลังส่งออก และการทดสอบความแม่นยำด้วยคลิปจริงหลายภาษา
- สถานะส่งมอบอยู่ในซอร์สที่เครื่อง ยังไม่ได้เผยแพร่การเปลี่ยนแปลงรอบนี้หรืออัปเดตคอนเทนเนอร์ที่เปิดใช้งาน

## งานต่อเนื่อง — คิวและประวัติช็อต

เพิ่มปุ่มเริ่มจากโฟลเดอร์และตารางประวัติ Kill แยกตาม SHA-256 ของไฟล์กับเวลาเหตุการณ์ เริ่มทดสอบการส่งออกซ้ำหลังเปลี่ยนชื่อไฟล์

- ปุ่ม Start folder queue สร้างคิวจากไฟล์ที่ลงทะเบียนแล้วและยังอยู่ในโฟลเดอร์ปัจจุบัน ณ ตอนกดเริ่ม ปุ่มเลือกคลิปเองยังใช้ได้
- ทดสอบวิดีโอสังเคราะห์ที่กำหนดให้มี Kill สองจังหวะ กดงานครั้งแรกได้หนึ่งช็อต เปลี่ยนชื่อไฟล์ก่อนรอบสองแล้วส่งออกอีกช็อต รอบสามจบโดยไม่มีไฟล์เพิ่ม ประวัติเก็บพร้อมรายการ Export ในธุรกรรมเดียวกัน ข้อมูล Export ของรุ่นเก่าไม่มีเวลา Kill สำหรับย้อนเติม
- Docker ทดสอบผ่าน 54 ข้อ ข้าม 1 ข้อเนื่องจากไม่มีวิดีโอเกมจริง ตรวจ API ของคิวและการเรนเดอร์แล้ว ยังไม่ได้ทดสอบการกดปุ่มผ่านเบราว์เซอร์จริงหรืออัปเดตคอนเทนเนอร์ Studio
- รุ่นนี้ยังส่งออกครั้งละหนึ่ง Reel การจำกัดจำนวนหลาย Reel ต่อครั้ง การทับภาพตามกติกา 45/15 วินาที และคะแนนหลัง Export เป็นงานต่อเนื่อง

## งานต่อเนื่อง — ส่งออกหลาย Reel

แยกการบันทึกผลออกเป็นราย Reel เพื่อให้เก็บไฟล์และประวัติช็อตของ Reel ที่ส่งออกสำเร็จได้ทันที กำลังตรวจการหยุดเมื่อครบจำนวนและการส่งออกที่ล้มเหลวระหว่างงาน

- เพิ่มตัวเลือกระยะสั้นและยาวแยกจากแนวนอนและแนวตั้ง คลิปสั้นจำกัด 180 วินาที หน้า Studio แสดงเพดานเวลารวมจากวินาทีต่อ Reel คูณจำนวนที่ตั้ง ค่าเริ่มต้นของคิวคือ 3 Reel ต่อครั้ง
- บันทึกไฟล์และประวัติแยกทีละ Reel ใช้ชื่อไฟล์เฉพาะแต่ละรายการ เมื่อ FFmpeg ของ Reel ที่สองล้มเหลวในกรณีทดสอบ ระบบลบไฟล์ที่ไม่สมบูรณ์และเก็บ Reel แรก งานถัดไปส่งออก 2 Reel ที่ค้างได้โดยใช้ผลตรวจ Kill เดิม
- เก็บช่วงต้นทางของแต่ละ Reel สำหรับตัดภาพซ้ำตามกติกา 45/15 วินาทีในช่วงต่อเนื่อง และตรวจการเปลี่ยนแปลงของต้นฉบับก่อนยืนยันการส่งออก
- เพิ่มประวัติ Export และคะแนนสี่ระดับใน Reel Inspector บันทึกคะแนนล่าสุดของแต่ละคลิปลง exports/ratings.json และตรวจว่าการเปลี่ยนจาก ดี เป็น ดีมาก ย้ายหนึ่งยอดนับ
- ปรับการครอปแนวตั้งให้ใช้พิกัดตามสัดส่วนของ preset ตรวจการเรนเดอร์จริงจาก 720p เป็น 1080 × 1920 โดยใช้ภาพกลางและภาพ killfeed จากเฟรมเดียวกัน

**ยืนยันผลรอบนี้** ชุดทดสอบ Docker ผ่าน 57 ข้อ ข้าม 1 ข้อเพราะไม่มีคลิป VALORANT จริง JavaScript หน้า Studio ผ่านการตรวจไวยากรณ์ งานตรวจจับหลายภาษาต้องใช้คลิปจริงที่เห็น Kill ของเจ้าของคลิปและช่วงที่ดูเพื่อนเล่น ส่วนช่องชื่อในเกมยังรอข้อมูลทดสอบว่าช่วยยืนยันผู้เล่นได้แม่นขึ้น การเปลี่ยนแปลงรอบนี้อยู่ในซอร์สบนเครื่องและทดสอบใน Docker แยกจาก Studio ที่ใช้งานอยู่

## ออกแบบหน้า Studio ใหม่

ศึกษาการรวมเครื่องมือที่ใช้บ่อยจาก [DaVinci Resolve Cut](https://www.blackmagicdesign.com/products/davinciresolve/cut) และการจัดคลังสื่อกับงานรีวิวจาก [Frame.io](https://frame.io/) นำมาจัดคลังคลิปไว้ข้างแผงตั้งค่าการส่งออก ใช้สีเขียวกับปุ่มเริ่มคิว และเพิ่มทางเข้าตั้งค่าโฟลเดอร์ในคลังว่าง
