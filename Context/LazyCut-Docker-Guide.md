# ใช้งาน LazyCut ผ่าน Docker Desktop

## เปิดใช้งานบน Windows

เปิด Docker Desktop ในโหมด Linux containers แล้วดับเบิลคลิก `start-docker.bat` ในโฟลเดอร์ LazyCut สคริปต์จะสร้างหรืออัปเดต image รอให้ Studio พร้อม แล้วเปิดเบราว์เซอร์ หากคอนเทนเนอร์กำลังทำงานอยู่ เปิด [LazyCut Studio](http://127.0.0.1:8000/) ได้ทันที

นำคลิปมาไว้ที่ `clips` จากนั้นเปิด **Studio Feed** แล้วรอให้รายการคลิปขึ้น กด **Create folder highlights** เพื่อสร้างจากโฟลเดอร์ หรือเปิด **Preview** เพื่อปรับจังหวะ และใช้ **Create from selected clips** สำหรับคลิปที่เลือก ไฟล์ MP4 และ chapters จะอยู่ที่ `exports`

## ใช้โฟลเดอร์คลิปที่มีอยู่

กำหนด `LAZYCUT_CLIPS_DIR` ในไฟล์ `.env` ที่โฟลเดอร์ LazyCut ด้วยพาธ Windows ของโฟลเดอร์ที่เก็บไฟล์วิดีโอโดยตรง ตัวอย่างเช่น

```dotenv
LAZYCUT_CLIPS_DIR="C:/Videos/Outplayed/Valorant"
```

เปิด `start-docker.bat` อีกครั้งเพื่อให้ Compose ใช้การตั้งค่าใหม่ ในหน้า Settings พาธที่แอปเห็นคือ `/clips` การเฝ้าโฟลเดอร์อ่านเฉพาะไฟล์ชั้นที่เลือก คลิปในโฟลเดอร์ย่อยต้องชี้ไปยังโฟลเดอร์นั้นโดยตรง ที่เก็บคลิปและ `music` เมานต์เข้า Docker แบบอ่านอย่างเดียว

## หยุดและเปิดใหม่

เปิด PowerShell ในโฟลเดอร์ LazyCut แล้วรัน

```powershell
docker compose stop
```

ใช้ `start-docker.bat` เปิดใหม่ได้ ฐานข้อมูล SQLite อยู่ใน Docker volume `lazycut_studio-data` และไฟล์ส่งออกอยู่ในโฟลเดอร์ `exports` บน Windows การเปลี่ยนโฟลเดอร์ที่เมานต์เป็น `/clips` อาจทำให้รายการคลิปเดิมอ้างถึงไฟล์ที่หาไม่พบ จึงควรใช้โฟลเดอร์เดิมสำหรับคลังเดียวกัน

## การตั้งค่าและผลทดสอบ

- Studio รับการเชื่อมต่อจากเครื่องนี้ที่ `127.0.0.1:8000` ใช้ Python 3.13 บน Linux และเข้ารหัสวิดีโอด้วย CPU ผ่าน `libx264`
- โหมด Docker ปิด Game Process Guard ของ LazyCut เพราะคอนเทนเนอร์ไม่เห็นโปรเซส VALORANT ที่รันบน Windows
- ตรวจเมื่อ 18 พฤศจิกายน 2569 หน้า Studio ตอบ HTTP 200 หลังรีสตาร์ต และยังใช้ไฟล์ SQLite เดิม คอนเทนเนอร์ทดสอบแยกยืนยันการเฝ้าโฟลเดอร์ วิเคราะห์คลิปสังเคราะห์ 4 วินาที เรนเดอร์ MP4 แนวตั้ง 2 วินาที และให้ดาวน์โหลดผ่าน API การทดสอบนี้ยังไม่ได้ใช้คลิป VALORANT จริง
