# Outplayed และแนวทางตัดไฮไลต์เกม FPS สำหรับ LazyCut

ตรวจแหล่งข้อมูลสาธารณะของผู้พัฒนาและสถานะ Overwolf วันที่ 18 พฤศจิกายน 2569 ขอบเขตหลักคือกลไกตรวจเหตุการณ์ การกำหนดช่วงคลิป และแนวทางที่นำไปใช้กับวิดีโออัดไว้แล้ว

สำหรับ LazyCut ให้เริ่มจากการตัดไฮไลต์จากวิดีโอหลังเกม โดยทำให้ผลตรวจ kill ใน Preview ตรงกับเหตุการณ์ที่ใช้เรนเดอร์ แล้วให้เลือกเหตุการณ์และปรับเวลาก่อน–หลังได้ การอัดสดด้วยเหตุการณ์ VALORANT เป็นงานระยะถัดไปที่ขึ้นกับความพร้อมของ provider และเงื่อนไขการเผยแพร่

## Outplayed ทำอะไรเมื่อเกิดเหตุการณ์ในเกม

- Outplayed ใช้แพลตฟอร์ม Overwolf ตรวจเหตุการณ์แบบเรียลไทม์ ตัวอย่างในคู่มือคือ Kill, Death และ Assist การรองรับแตกต่างกันตามเกม เพราะต้องมีการบำรุงรักษาและการอนุญาตจากผู้พัฒนาเกม ผู้ใช้เลือกได้ว่าจะบันทึกเหตุการณ์ประเภทใด. [Outplayed Quick Set-up Guide](https://support.overwolf.com/support/solutions/articles/9000284663-outplayed-quick-set-up-guide)
- โหมด **Highlights** สร้างคลิปรอบเหตุการณ์ที่เลือกและตั้งช่วงก่อน/หลังแยกตามประเภทเหตุการณ์ได้ คู่มือระบุว่าสูงสุด 180 วินาทีแต่ละด้าน โหมด **Full Match** บันทึกตั้งแต่เริ่มจนจบแมตช์ ส่วน **Full Session** บันทึกตั้งแต่เปิดจนปิดโปรเซสเกม ทั้งสองโหมดทำ bookmark ที่มีเวลาเริ่มและระยะเวลาในไทม์ไลน์ **Manual Capture** ให้ผู้ใช้เลือกจังหวะเอง และปุ่มลัดสามารถเพิ่ม bookmark เมื่อมีการบันทึกอัตโนมัติอยู่. [How to use Outplayed](https://support.overwolf.com/support/solutions/articles/9000284659-how-to-use-outplayed)
- เมื่อ game events ขัดข้อง Outplayed ระบุว่า Highlights และ Full Match จะสลับไปบันทึก Full Session และจะขาด bookmark อัตโนมัติ ผู้ใช้จึงยังมี footage ให้ย้อนดู. [How to use Outplayed](https://support.overwolf.com/support/solutions/articles/9000284659-how-to-use-outplayed)
- **Supercut** เป็นพฤติกรรมที่ใกล้กับ LazyCut ผู้ใช้เลือกแมตช์ ประเภทเหตุการณ์ และ Pre/Post จากนั้นระบบสร้างวิดีโอรวมแยกจากไฟล์แมตช์ คู่มือยก Kill, Death, Assist, Clutch และ Headshot เป็นตัวอย่างของตัวเลือกในหน้าจอ การใช้ตัวเลือกเหล่านี้กับ VALORANT ต้องตรวจจากแอปและแมตช์จริง. [Outplayed Supercut](https://support.overwolf.com/support/solutions/articles/9000284659-how-to-use-outplayed#How-to-use-the-Supercut-feature)
- Editor รับคลิปจากภายนอกมารวม ตัดต่อ และทำ montage ได้ ส่วน FAQ ระบุว่า MP4 ที่นำเข้าจะไม่มี metadata ประเภท game events, เกมที่บันทึก, วันเวลาต้นทาง และ APM จากการนำเข้าไฟล์เพียงอย่างเดียว. [Outplayed Video Editor](https://support.overwolf.com/support/solutions/articles/9000284658-how-to-use-the-outplayed-video-editor), [Outplayed FAQ](https://support.overwolf.com/en/support/solutions/articles/9000209065-outplayed-faq)

## กลไกในเอกสาร Overwolf SDK

- Overwolf Native เปิด background replay capture ด้วย `overwolf.media.replays.turnOn()` ตัวอย่าง SDK มีทั้งปุ่มจับ replay และให้แพลตฟอร์มทริกเกอร์อัตโนมัติ รูปแบบ `capture(pastDuration, futureDuration, …)` รับช่วงก่อนและหลังคำสั่งหน่วยมิลลิวินาที `startCapture(pastDuration, …)` ให้เริ่มจากอดีตแล้วหยุดเมื่อเกิดเงื่อนไขในภายหลัง เช่น จบคอมโบ และ `getHighlightsFeatures()` ใช้ตรวจชนิดไฮไลต์ที่เกมรองรับ. [Overwolf Replays API](https://dev.overwolf.com/ow-native/reference/media/replays/)
- ระบบ auto-highlights ของ SDK อธิบาย `past`, `future` และ `pending` เป็นค่าต่อชนิดเหตุการณ์ `pending` คือช่วงรอเหตุการณ์ถัดไปเพื่อรวมคลิป เช่น Kill ตามด้วย Death อาจรวมเป็นไฟล์เดียวตามค่า pending ของ Kill เอกสารยกค่าตัวเลขจาก League of Legends เป็นตัวอย่าง การใช้กติกานี้กับ LazyCut เป็นข้อเสนอจาก SDK ส่วนกติกาการรวมคลิปที่ Outplayed ใช้จริงและค่าเฉพาะ VALORANT ยังไม่มีหลักฐานในคู่มือที่ตรวจ. [Overwolf Auto-highlights Supported Games](https://dev.overwolf.com/ow-native/guides/general-tech/auto-highlights-supported-games/#how-it-works)
- ตัวอย่าง callback `onHighlightsCaptured` ของ SDK มีรายการเหตุการณ์พร้อมเวลาและ `replay_video_start_time` จึงใช้เป็นแบบอย่างในการเก็บเวลาเหตุการณ์คู่กับเวลาอ้างอิงของวิดีโอ เอกสารให้จับคู่ `match_id` ของ callback กับ `pseudo_match_id` ที่เกี่ยวข้องตาม contract นั้น ควรตรวจชนิด ID และความหมายของเวลาใน provider จริงก่อนใช้เชื่อมข้อมูล Riot หรือสร้างไฟล์สื่อประกอบ. [Overwolf Replays API](https://dev.overwolf.com/ow-native/reference/media/replays/#onhighlightscaptured)
- Overwolf GEP แยก **one-off events** เช่น kill กับ **info updates** เช่น game/round state โดยต้องลงทะเบียน features ในแอป Overwolf ก่อน หากเชื่อม SDK ควรตรวจสุขภาพราย feature แยกจากระดับเกม และอย่าเขียนข้อมูลดิบ GEP ลง log ตามคำแนะนำผู้ให้บริการ การคงหรือส่ง metadata ที่มาจาก GEP ต้องตรวจข้อกำหนดผู้ให้บริการและ Riot ก่อน. [GEP Overview](https://dev.overwolf.com/ow-native/live-game-data-gep/live-game-data-gep-intro/), [Overwolf Games Events API](https://dev.overwolf.com/ow-native/reference/games/events/), [GEP Status API](https://dev.overwolf.com/ow-native/live-game-data-gep/verifying-events-for-your-app/)

## VALORANT รองรับอะไรและมีข้อจำกัดตรงไหน

- หน้าร้าน Outplayed แสดง VALORANT เป็นเกมที่รองรับและแสดงรุ่นวันที่ 16 พฤศจิกายน 2569 รายชื่อของ Overwolf Native SDK ก็มี VALORANT ประกาศเก่าเคยระบุ auto-highlight สำหรับ Kill, Death และ Assist ส่วน GEP มีเหตุการณ์และ state มากกว่า รายการของแต่ละระดับจึงมีขอบเขตต่างกัน. [Outplayed Store](https://www.overwolf.com/app/overwolf-outplayed), [Auto-highlights Supported Games](https://dev.overwolf.com/ow-native/guides/general-tech/auto-highlights-supported-games/), [Overwolf Changelog Archive](https://dev.overwolf.com/ow-native/support/changelog-archive/ow-changelog/)
- VALORANT ID `21640` อยู่ในสถานะ `2` / `101` (Partial availability) ใน API รวมของ Overwolf ที่เปิดดูในวันที่ตรวจ ซึ่งแสดง `disabled: false` และ GEP ขั้นต่ำ `317.4.3` changelog เดือนพฤศจิกายนระบุว่า `317.4.3` แก้ game events ของ VALORANT การตรวจนี้ยืนยันสถานะรวม ระดับรายเหตุการณ์และผลการทำงานในแมตช์จริงยังไม่ได้ยืนยัน เพราะเครื่องมือดึง endpoint รายเกมไม่ได้และไม่มีการทดสอบในเกม. [Overwolf Status Feed](https://game-events-status.overwolf.com/gamestatus_prod.json), [Event Health Levels](https://dev.overwolf.com/ow-native/live-game-data-gep/verifying-events-for-your-app/#event-health-levels), [Overwolf Changelog](https://dev.overwolf.com/ow-native/getting-started/changelog/ow-changelog/)
- **Local kill/death เทียบกับ kill feed** `kill`, `assist`, `headshot` และ `death` มีข้อมูลเป็นยอดสะสมของผู้เล่นท้องถิ่น ให้ตรวจการเพิ่มขึ้นและการรีเซ็ตของยอดเมื่อจับคู่กับ info updates `kill_feed` เป็นเหตุการณ์เมื่อ feed ปรากฏบน UI มี attacker, victim, assists, weapon, headshot flag และ team flags ตัวอย่าง feed ยังมี non-lethal ultimate จึงต้องยืนยันตัวผู้เล่นและชนิดรายการก่อนนับเป็น kill ส่วน event `headshot` หมายถึงเกิด headshot หากจะตีความว่าเป็น **headshot kill** ให้ยืนยันจาก flag บน kill-feed entry หรือข้อมูลผลการดวลประกอบ. [VALORANT GEP Events](https://dev.overwolf.com/ow-native/live-game-data-gep/supported-games/valorant/)
- **Round/match/objective** ใช้ `round_number` และ `round_phase` (`shopping`, `combat`, `end`, `game_end`) ประกอบขอบเขตรอบ เอกสารระบุ `match_end` ใช้ไม่ได้ใน custom หรือ training `spike_defused` และ `spike_detonated` เป็น one-off events แต่ `planted_location` ส่งตำแหน่ง A/B/C ตอนจบรอบสำหรับรอบที่วาง Spike จึงไม่ใช่เวลาเริ่มวาง. [VALORANT Match Info and Events](https://dev.overwolf.com/ow-native/live-game-data-gep/supported-games/valorant/#match_info)
- การเผยแพร่แอป VALORANT บน Overwolf ต้องให้ทั้ง Riot และ Overwolf อนุมัติก่อน ตามเอกสารไม่มีการรับ private apps สำหรับ VALORANT และตั้งแต่ 1 พฤศจิกายน 2569 การอนุมัติแอปใหม่ของ Overwolf ต้องมีช่องทาง monetization ของ Overwolf. [Overwolf Riot Games Compliance](https://dev.overwolf.com/ow-native/guides/game-compliance/riot-games/), [Overwolf Monetization](https://dev.overwolf.com/ow-native/monetization/overview/)
- Riot ระบุว่าเริ่มบล็อกการอ่านหน่วยความจำเกมจากแอปภายนอกที่ไม่รู้จักตั้งแต่ 6 ตุลาคม 2569 แอปที่รู้จักและได้รับอนุมัติเดิมได้ระยะเปลี่ยนผ่านถึงเมษายน 2570 โดย Riot ไม่รับประกันการทำงานของแอปใด นโยบาย VALORANT Developer API กำหนดการขึ้นทะเบียนผลิตภัณฑ์ที่ให้บริการผู้เล่น สำหรับ API ข้อมูลเกม เอกสารแสดงการดึงประวัติแมตช์และแมตช์ตาม ID ปัจจุบันไม่รองรับ Personal Key Applications และการเข้าถึงข้อมูลส่วนบุคคลผ่าน Riot Sign On (RSO) ใช้ production key และการ opt-in ข้อมูลหลังเกมอาจช่วยตรวจเทียบได้เมื่อเข้าถึงโดยได้รับอนุญาตและซิงก์เวลาเข้ากับไฟล์แล้ว. [Riot Game Memory Access Policy](https://support.riotgames.com/en-us/riot/performance/game-memory-access-removed-for-third-party-apps), [Riot VALORANT Developer Policy and APIs](https://developer.riotgames.com/docs/valorant)

## แนวทางพัฒนาเรียงตามลำดับ

เส้นทางที่เสนอคือ **นำเข้าไฟล์ → ตรวจเหตุการณ์ → บันทึกเหตุการณ์พร้อมเวลา → เลือกช่วงใน Preview → เรนเดอร์ช่วงที่เลือก** เมื่อรองรับแหล่งเหตุการณ์เพิ่มเติม ให้แปลงข้อมูลมาเป็นตำแหน่งบนไทม์ไลน์ของไฟล์เดียวกันก่อนส่งให้ตัวเลือกช่วง ตัวอย่างเช่น bookmark เวลา 25 วินาทีของวิดีโอเต็มแมตช์จะอ้างอิงไฟล์และไทม์ไลน์คนละชุดกับคลิปย่อย 10 วินาทีที่ตัดจากแมตช์นั้น

### 1. ใช้ผลวิเคราะห์ชุดเดียวตั้งแต่นำเข้าถึงเรนเดอร์

- ให้ Watch Folder, Rescan, Import และ Preview ขอผลจากเส้นทางวิเคราะห์เดียวกัน เข้าคิวหลังไฟล์พร้อมอ่าน ใช้พาธที่ปรับรูปแบบแล้ว ขนาด เวลาแก้ไขไฟล์ และเวอร์ชัน detector/preset เพื่อตรวจว่าควรสแกนใหม่หรือใช้ผลเดิม ตรวจสถานะไฟล์อีกครั้งก่อนบันทึกผลหากไฟล์เปลี่ยนระหว่างงาน
- เก็บเวลาเหตุการณ์บนไทม์ไลน์ของไฟล์ ชนิดเหตุการณ์ แหล่งที่มา และสถานะการตรวจแยกจากจำนวน kill ใช้สถานะ `pending`, `analyzed`, `failed` เพื่อให้ผู้ใช้แยกคลิปที่ยังไม่ได้สแกนออกจากคลิปที่สแกนแล้วพบ 0 เหตุการณ์ ค่าคะแนนจาก template และสีควรแสดงเป็นคะแนนหลักฐานจนกว่าจะมีข้อมูลสอบเทียบ
- เปลี่ยนเหตุการณ์อัตโนมัติและสรุปจำนวนของผลสแกนรอบเดียวกันในธุรกรรมเดียว ทำให้ retry หรือเหตุการณ์ Watchdog ซ้ำไม่เพิ่มรายการซ้ำ เก็บ manual bookmark แยกจากผลสแกน และให้ compositor อ่านผลเวอร์ชันเดียวกับที่ Preview แสดง คลิปเก่าที่ไม่มีข้อมูลเวอร์ชันให้เข้าคิววิเคราะห์เมื่อถูกใช้
- ให้ Game Process Guard เลื่อนคิวสแกนและเรนเดอร์ที่ยังไม่เริ่ม แล้วทำต่อหลังเกมปิด จัดการงานที่ค้างหากโปรแกรมปิดระหว่างทำงาน แสดงเหตุที่รอหรือผิดพลาดใน Studio และเก็บไฟล์ต้นฉบับไว้ตามพาธเดิม

### 2. ตรวจเหตุการณ์ระดับแถว แล้วค่อยสร้างช่วงไฮไลต์

- ให้ detector คืนกรอบและหลักฐานของแต่ละแถว รวม headshot เฉพาะแถวนั้น ติดตามแถวข้ามเฟรมโดยใช้ลักษณะภาพร่วมกับตำแหน่ง เพื่อรับมือการเลื่อนเมื่อมีแถวใหม่ เก็บ timestamp ของการปรากฏครั้งแรกที่ยืนยันได้ และเพิ่มหนึ่ง event ต่อแถวใหม่ ทดสอบกรณี HUD มี killfeed อยู่ตั้งแต่เฟรมแรกโดยทำเครื่องหมายว่าอาจเป็นเหตุการณ์ก่อนคลิปเริ่ม
- กำหนด ROI สำหรับตรวจจับและค่า template/สีตามภาษาและรูปแบบ HUD ใน preset ระบุ 1080p ภาษาไทยเป็นฐานทดสอบก่อน ขยายไปภาษาและสเกลอื่นเมื่อมีคลิปติดป้ายกำกับ ใช้ระดับเสียงช่วยจัดอันดับช็อตที่ยืนยันแล้วหรือพาผู้ใช้ไปจุดตรวจใน Preview
- สร้างช่วงจาก event ที่เลือก ให้ผู้ใช้ตั้ง pre/post ตามชนิดและปรับเองใน Preview ตัดให้อยู่ในขอบไฟล์ รวมช่วงทับกันโดยคงหลาย event ในช่วงเดียว จัดอันดับเพื่อเลือกช่วงในงบเวลา แล้วเรียงช่วงที่เลือกตามเวลา เก็บเฟรมเหตุการณ์หลักไว้เสมอเมื่อย่อ ถ้างบไม่พอให้ข้ามช่วงนั้นหรือแจ้งเหตุให้ผู้ใช้เลือกเอง ตัวอย่างทดลอง `kill @ 10.0s` และ `kill @ 10.8s` ต้องได้ 2 เหตุการณ์ แต่ส่งออกเป็นช่วงเดียวได้
- ใช้ timestamp ของสื่อจริงเมื่อทดสอบไฟล์ VFR และตรวจ A/V sync กับผลงานเรนเดอร์ ตรวจคลิปที่มีหลายแทร็กเสียงและคลิปไม่มีเสียงด้วย หากทำตัวเลือกส่งออกเร็วแบบ stream copy ให้ตรวจผลเทียบคีย์เฟรม FFmpeg ระบุว่า input seek อาจไปยัง seek point ก่อนเวลาเป้าหมาย และการ transcode ที่เปิด `accurate_seek` จะตัดช่วงเกินออก. [FFmpeg -ss และ accurate seek](https://ffmpeg.org/ffmpeg.html#Main-options)
- ก่อนรองรับ Full Match ให้ทดสอบการอ่านแบบต่อเนื่องทีละช่วงเพื่อจำกัดหน่วยความจำและเก็บ progress ได้ วัดเทียบกับ `curate_clip()` ที่ปัจจุบัน seek ทีละตัวอย่างและดึงเสียง PCM ของไฟล์เข้า stdout ภายใต้ timeout 15 วินาที ให้คงสถานะการติดตามแถวข้ามรอยต่อเพื่อหลีกเลี่ยงการนับซ้ำ. [Curator](https://github.com/posawatwichitsaro-bit/LazyCut/blob/325ad2a0e2c25c38bea641d494204d53b292b851/backend/app/detection/highlight_curator.py#L167)

## วิธีวัดผลก่อนตัดสินใจเพิ่มระบบอัดสด

ตัวเลขต่อไปนี้เป็นเกณฑ์ทดลองที่เสนอ ให้รัน baseline และเวอร์ชันปรับปรุงบนชุดเดียวกันก่อนยืนยันเป้าหมายจริง

| ด้าน | ชุดทดสอบและเกณฑ์ที่เสนอ |
| --- | --- |
| ความถูกต้อง | ทำชุดคลิปที่ผู้ใช้อนุญาตและติดป้ายเวลาเหตุการณ์ด้วยมือ แยกชุดปรับค่ากับชุดประเมินตามแมตช์ เริ่มจากไทย 1080p ให้มี kill เดี่ยว, double/triple เร็ว, แถวค้าง, kill ของเพื่อน, ช่วงเดิน, spectator และคลิปเริ่มกลางเหตุการณ์ จับคู่ผลกับป้ายแบบหนึ่งต่อหนึ่งในช่วง ±0.75 วินาที รายงาน precision/recall และความคลาดเวลา P95 แยกตามกลุ่ม เป้าทดลอง precision ≥95%, recall ≥90% ในภาษาไทย 1080p พร้อมรายงานจำนวนตัวอย่าง |
| การรวมช่วงและความยาว | ทดสอบเหตุการณ์ใกล้ต้น/ท้ายคลิป หลาย kill ในช่วงเดียว และเวลาที่เหลือสั้นกว่า pre-roll ตรวจว่า event หลักทุกตัวที่ติดป้ายในผลงานอยู่ในช่วงภาพจริง และไม่มีภาพช่วงเดียวกันถูกซ้ำจากการรวมช่วงบนไฟล์เดียวกัน ตรวจทั้ง 9:16 และ 16:9 |
| ความสอดคล้อง | ให้ Watchdog ส่ง callback ซ้ำ สแกนซ้ำ เปิด Preview หลายครั้ง สร้าง montage และปิดเปิดแอประหว่างคิว จำนวน event อัตโนมัติต้องคงเดิมสำหรับไฟล์และ detector เวอร์ชันเดิม ตรวจกรณีไฟล์เปลี่ยนและกรณีคลิปต้นฉบับหายด้วย |
| ทรัพยากร | วัดเวลาวิเคราะห์ต่อความยาววิดีโอ ขนาด cache และเวลาเปิด Preview รอบแรก/รอบซ้ำ ถ้าจะทำระบบอัดสด ให้เพิ่ม FPS ในเกม, P95 frame time, dropped frames, disk usage และเวลาจาก event จนไฟล์พร้อม เทียบกับเครื่องและ settings เดียวกันโดยเปิดและปิดฟีเจอร์ |
